# v11 audio correction — 2026-11-01

## Confirmed root cause

The demo dynamically creates Game, Music and FX buses using `AudioServer.add_bus()`.
In Godot 4.6.3 C++, appending is passed to Web as index `-1`; the shipped JavaScript
`Bus.addAt(-1)` moves the new bus ahead of Master. Later sends then use mismatched
native/Web indices, leaving all four sample buses disconnected from the output.

The regression extracts the **actual shipped engine Bus class**, reproduces the
broken graph, and verifies the corrected graph. Native source confirms the `-1`
append path; explicitly passing `add_bus(bus_count)` would still normalize to -1.

Fix: `AudioSettings._ensure_bus` grows `AudioServer.bus_count` instead. The existing
names, FX→Game→Master / Music→Game→Master hierarchy, saved volume/mute choices and
low-latency Sample playback remain intact. No engine-JS patch, global Stream
workaround, settings reset, or assumption that the user muted audio.

## Cue readability and ownership

Previous procedural charge/release were identical .25s waveforms, roughly -33dBFS
peak / -42dBFS RMS after player gain. New original deterministic PCM separates:

| Cue | Duration | Peak dBFS | RMS dBFS |
|---|---:|---:|---:|
| Casting build | .60s | -10.50 | -17.83 |
| Release/fizzle | .20s | -10.50 | -24.20 |
| Impact | .23s | -10.50 | -25.90 |
| Healing | .40s | -10.50 | -20.80 |

Levels precede user bus gain. Only authored-demo Fire's `fire_charge` uses the
new build; original WAV, legacy Fire behavior, cue identity and phase-end/cancel
voice ownership are preserved. No costs, damage, statuses or turn rules changed.
